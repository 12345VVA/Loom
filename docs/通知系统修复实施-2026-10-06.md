## 五、执行结果（关键改动）

### 5.1 后端

- **`_insert_recipients`（F1，`notification_service.py:615-639`）**
  删除循环内逐用户查重，改为一次性 `select(NotificationRecipient.user_id).where(message_id==…, user_id.in_(candidate_ids))` 取 `existing_ids`，仅对差集构造行并 `self.session.add_all(rows)`。
  **实测（N=5）：查重 SELECT 由 5 → 1。**

- **`unread_count`（F2，`:147-166`）**
  `conditions` 元组抽出复用；`select(func.count(NotificationRecipient.id))…one()` 返回标量 `int`。

- **`list_for_user`（F3a，`:94-145`）**
  签名新增 `limit/offset`；归档过滤下推（`not include_archived → is_archived==False`／`include_archived and read_status=='archived' → is_archived==True`）；循环体只剩构造 dict。

- **`resolve_recipients`（F4，`:589-591`）**
  两分支合并，统一要求 `is_active`。

- **`mine`（F3b/R1′，`controller/admin/message.py:68-92`）**
  `limit: int = 0, offset: int = 0`（0 = 不限制，默认行为不变），夹取后以 `limit or None` 透传服务层。代码内注释写明了"为何不用 `int | None`"（指向生成器 469 行），避免后人踩回同坑。

### 5.2 前端

- **`toolbar-notice.vue`（F5）**：`showDetail` 就地置已读并把未读数递减（去掉两次重新拉取）；新增 `tick()`/`onVisibility()` + `visibilitychange` 监听/注销；`refresh()` 的 `mine` 传 `limit: 8`。
- **`message.vue`（F6）**：`isRead`/`isArchived` 改具名插槽 `{{ row.isRead ? $t('是') : $t('否') }}`。
- **`my-notification.vue`（F7）**：`mine({ ...query, limit: 50 })`。

### 5.3 产物与契约

- `frontend/build/cool/eps.d.ts`：`mine` 补 `limit?: number; offset?: number;`（**与 HEAD 的 diff 恰为 2 行插入**）。
- `backend/eps_baseline.json`：重生成。
- `frontend/build/cool/eps.json`（未入库缓存）：`mine` 的 `limit/offset` schema 由 `anyOf` 改为 `{"type":"number","default":0}`。

### 6.2 R1′ 的闭环验证（本轮最关键的一条）

判据是「**产物与生成器的产物自洽**」，而非"手工改绿"：

```
修复前：mine.limit.schema = {"anyOf":[{"type":"number"},{"type":"null"}]}   → 生成器会产 limit?: string ✗
修复后：mine.limit.schema = {"type":"number","default":0,"title":"Limit"}   → 生成器会产 limit?: number ✓
命令：dump_eps.py --check → OK；vue-tsc → exit 0
```

即：`eps.d.ts` 的 `limit?: number` 现在**正是"用新签名重生成"的结果**，而不是靠人工维持的偏离态。

### 6.3 已知遗留观察（非阻塞）

1. **`limit=0` / 负数语义为「不限制」**：前端只发正数（toolbar `8`、my-notification `50`），无用户面影响；默认不传亦为"不限制"，向后兼容。
2. **`my-notification` 传 `limit: 50` 会在 >50 条时静默截断**（取最新 50）。`offset` 服务端已具备，如需「加载更多」可后续补 UI。
3. **F5 的行为变化**：点击未读项后该条**不从列表移除**（旧版 `refresh()` 会重拉使其消失）。判定为**可接受**——弹层每次打开 `@show="refresh"` 会重拉，陈旧窗口被限制在单次弹层会话内，且请求数 4 → 2。

### 方法论沉淀

1. **"门禁绿"≠"正确"**：手改产物能让 `vue-tsc` 变绿，但产物与生成器输出不自洽即为埋雷。验收标准应是「**产物 == 生成器的产物**」，判据必须能证伪（本例：比 `dump_eps` 导出的 schema 是否有顶层 `type`）。
2. **改 API 面必须连带重生成**：后端路由/入参变更 → `eps.d.ts` + `eps_baseline.json` 同步是**强制**步骤（CI 有门禁）。
3. **本仓库暴露新接口参数的硬约束**：**GET 的数字查询参数不要写 `int | None = None`**，否则 EPS 生成器回退成 `string`。应写 `int = <默认值>`（参照 `captcha` 的 `width: int = 150`）。
