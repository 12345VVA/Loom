# 验证码攻击破解逻辑分析（2026-10-06）

> **定位**：本文不是又一份测试报告，而是把三轮验收中分散的攻击**收敛到机制层**的解释——这套滑块验证码**为什么能被解开**、以及**换任何图像加固都解不开的那部分在哪**。
>
> **上游报告**：`docs/验证码加固版验收测试-2026-10-05.md`（`5ce70ee`）、`docs/验证码加固版二次验收测试-2026-10-06.md`（`5a7d074`）、`docs/验证码加固版三次验收测试-2026-10-06.md`（`64fb3c8`）。
> **证据集**：`deliverables/登录验证码-2026-10-05/hardening-verify/`。
>
> **结论先行**：破解的本质是把验证码**降维成「定位唯一暗区」**——服务端手里的秘密、人类的任务、攻击者所需，三者是同一个数（缺口的 x 坐标）。四条通道里，**两条是结构性的**（亮度、色度），任何图像加固都拆不掉。

---

## 1. 破解的本质：定位即答案

### 1.1 校验契约（源码）

`backend/app/modules/base/service/auth_captcha.py` → `captcha_check()`：

```python
if abs(final_x - target_x) > tolerance:
    raise HTTPException(401, "验证码不正确或已失效")
```

- **只比对 x**，容差 `CAPTCHA_SLIDER_TOLERANCE = 12`；全文**没有任何 y 校验**。
- 轨迹校验（时长 ≥450ms、点数 ≥6、时间轴单调非递减、回退限幅、末点与 `final_x` 一致）都是**弱防护**——脚本可伪造一致时间轴，源码注释亦自承「定位是弱防护」。

### 1.2 响应契约（源码）

同文件 `captcha()`：

```python
"sliderY": target_y,     # ← 缺口纵坐标，明文下发
```

即**服务端把答案的一半直接送给了客户端**。

### 1.3 推论

| 角色 | 需要的信息 |
|---|---|
| 服务端持有的秘密 | 缺口的 **x** 坐标 |
| 人类的任务 | 找到缺口，把滑块拖到它的 **x** |
| 攻击者需要的 | 缺口的 **x** 坐标 |

**三者完全重合。** 只要缺口能被机器定位，验证码的判据就被完全满足——不存在「人类能做、机器不能做」的间隙。

### 1.4 单缺口模式删掉的是哪一层

| 模式 | 攻击者要做的 | 服务端隐藏的信息 |
|---|---|---|
| 多缺口（`DECOY>0`） | ① 定位所有候选 ② **从候选中判别真假** | 缺口 x **+ 哪一个是真缺口** |
| 单缺口（`DECOY=0`，`5a7d074` 终局） | ① 定位唯一缺口 | 缺口 x |

`5a7d074` 把 `DECOY` 归零，**删掉的不是伪缺口，是「判别真假」这道题本身**。于是攻击退化为纯定位，而纯定位有四条 90–100% 的独立通道。

> **口径警告**：官方基准的 `随机下界 = 1/k` 在 k=1 时**恒为 100%**，于是「任何策略都不优于下界」自动成立、**不可否证**——它把「定位」这一步的收益记成了免费。**真实盲猜下界是 `(2×12+1)/257 ≈ 9.7%`**（不放图、x 均匀随机）。

## 2. 泄漏通道：缺口不是「泄漏」出来的，它就是渲染产物

缺口由 `render_slider_captcha()` → `paste_hole()` 分三步叠加烧制：**暗块 → 洞内噪声 → 高饱和色调**。每一步都留下一个机器可读的印记。

| # | 通道 | 渲染层成因（源码位置） | 机器提取方式 | 攻击 | 命中率 | 状态 |
|---|---|---|---|---|---|---|
| ① | **亮度** | `paste_hole` 叠 `_HOLE_DARK_ALPHA=110` 暗块；洞内噪声均值取 `_hole_noise_mean = 0.57×` 局部背景 | L 通道 `size×size` 滑窗均值 `argmin` | A3 / A4 | **91.7%** | 仍开放 |
| ② | **色度** | `tint_alpha=150` 高饱和叠加；`_random_bg_color` 强制三通道同值（背景真灰 `S=0`） | HSV `S>70` 二值化 → 连通块 / 滑窗 `argmax` | A1 / A2 | **100%** | 仍开放 |
| ③ | **形状** | `piece.putalpha(hole_mask)` —— 拼图块 alpha **恒等于**洞掩码（构造性咬合） | 暗区分割得洞掩码 → bbox 归一化 → IoU | S6 | **100%** | 多缺口模式下开放（单缺口下无判别价值） |
| ④ | **坐标侧信道** | `captcha()` 下发 `"sliderY": target_y`，而校验**只比 x** | 挑 y 最接近 `sliderY` 的候选 | S3 | **96.7%** | 多缺口模式下开放 |
| ⑤ | **明度序** | 旧版 `pick_tints` 的 `value = 235 - index*40`，`tints[0]` 恒为真缺口且**最亮** | 掩码内均值色 `argmax` | S7 | 99.2% | **已修**（现加 `rng.shuffle` 与明度解绑） |

**关键区分**：①② 是**结构性**的——为了让「洞看起来像一个洞」（暗、有颜色），这些特征必须存在；③ 是**构造性**的——咬合要求拼图块形状必须等于洞形状。它们不是「不小心多带的信息」，而是**任务本身的实现方式**。⑤ 与 ④ 是**设计选择**造成的，可以改。

## 3. 攻击策略全集

### 3.1 离线基准（多缺口模式，seed=20261005，n=120，真值取自渲染管线 `decoys`）

| 策略 | 原理 | 命中率 |
|---|---|---|
| S1 | §13 亮度反向补偿（`×255/145`）+ 滑窗模板匹配 | **20.8%**（低于随机下界） |
| S2 | 定位后随机挑一个（对照下界） | 40.6% |
| S3 | 描边/暗区定位 + 取 y 最接近 `sliderY` 者 | **96.7%** |
| S4 | 候选框均值色调匹配（粗） | 70.8% |
| S5 | y=`sliderY` 行内最暗窗口 | 64.2% |
| S6 | **形状比较器**：暗区提掩码 → bbox 归一化 → IoU | **100.0%** |
| S7 | **明度通道**：掩码内均值最亮者 | **99.2%** |
| — | 缺口定位正确率（仅定位这一步） | 100.0% |

### 3.2 独立第三方基准（单缺口模式，240 样本，A1–A4）

| 策略 | 单独原理 | 05 种子 | 06 种子 |
|---|---|---|---|
| A1 | HSV `S>70` → 开运算 → 最大连通块 bbox | **100.0%** | **100.0%** |
| A2 | `S` 的 44×44 滑窗均值 `argmax` | **100.0%** | **100.0%** |
| A3 | L 的 44×44 滑窗均值 `argmin`（**完全不用色调**） | 91.7% | 85.0% |
| A4 | `L <` 分位阈值 → 连通块 bbox（**完全不用色调**） | — | — |
| — | 真实盲猜下界 | 9.7% | 9.7% |

**A3/A4 的意义**：即便色度通道被堵死，纯亮度通道仍 >85%。两条通道**互相独立**，堵一条没有任何净收益。

### 3.3 浏览器端到端（真实指针事件，`currentX` 与服务器 x 1:1）

- **对照实验**：拖到正确位置 → 「用户名或密码错误」（验证码通过）；偏 +70px → 「验证码不正确或已失效」。**排除校验失效的可能**。
- **S3** 批量 **5/5 通过**，预测 6/6 全中。
- **两条独立路径各自完整登入**（均 `admin`）：S3（x=239）→ **HTTP 200** + JWT + 196 权限；S6（x=141，**不用色调、不用 sliderY**）→ **HTTP 200** + JWT。
- 单缺口模式：A1/A2/A3 三通道给出 x=72/72/74 互证 → 拖动 72 → **HTTP 200 + JWT + 跳首页**。

## 5. 为什么「图像加固」有天花板

### 5.1 一条信息论式的不变式

> **验证码必须「人类可解」；而「人类靠什么找到缺口」的特征，按定义就是「机器靠什么找到缺口」的特征。**

逐条论证（全部不可回避）：

| 要让人类做到 | 图像里必须存在 | 机器因此可以 |
|---|---|---|
| 看出「这里有个洞」 | 洞与背景**有对比** | 阈值分割 / `argmin` / `argmax` |
| 看出「洞是彩色的」 | 洞**有饱和度** | HSV `S>70` |
| 完成咬合 | 拼图块形状 **=** 洞形状 | 掩码 IoU |
| 知道往哪个高度拖 | （前端需要 `sliderY`） | 直接读响应字段 |

**没有任何一项是「多余的泄漏」——删掉任何一项，任务对人类也不成立。**

### 5.2 加固真正打掉的只有一层

三代唯一真正失效的攻击是 **S1（内容相关性利用）**：v1 用 `σ=25` 洞内噪声把「洞内 = 原图 × 常数」的确定性关系**结构性切断**，再用「补偿寄存器呈现拼图块」让模板匹配被**主动误导**（20.8% 低于随机下界 40.6%）。

这说明：
- **内容层**（洞内像素与背景的数学关系）→ **可防**，且 `5ce70ee` 防得很漂亮；
- **结构层**（洞比背景暗、比背景饱和、与拼图块同形）→ **不可防**，因为那是任务本身；
- **契约层**（`sliderY` 下发、只校验 x）→ **可修**，但与图像无关。

### 5.3 范式结论

**滑块拼图范式的「图像加固」在原则上有天花板。** 能做的只有：
1. 堵**契约层**漏洞（不下发 `sliderY`、补 y 校验）；
2. 重新引入**判别维度**（多缺口 + 同形 + 洗牌，把 k 提高到 >1），但需明示接受「A1/A2 恒 100% 的定位通道」；
3. 换**范式**（如 PoW / 行为式，见 `docs/开源行为验证与拼图验证码调研-2026-10-05.md` 推荐的 ALTCHA）。

**唯一不能做的**：宣称「图像加固把抗解能力拉回盲猜水平」——S1=0% 只意味着击败了**§13 类通用模板匹配工具链**，它覆盖的攻击空间远小于真实攻击者的空间。

## 6. 与 R2 账号锁 DoS 的因果连接（上一轮的终点）

验证码失效不是「一个独立的问题」，它**翻转了下游防线的语义**：

```
验证码可解（A1/A2 = 100%）
  → 越过 captcha_check，抵达凭证校验
  → 错密码分支 count_account=True（auth_login.py:95-101）
  → 计满 ACCOUNT_FAIL_MAX=5，写 login:lock:account:{user}
  → _check_login_risk 在 captcha_check **之前**执行
  → 正确凭证也被 429
```

**实测**：B 组（已解票 × 错密码）5/5 验证码全过、耗时 **2.1 秒**、账号计数 1→5、锁位置位；C 组（**正确密码** + 已解票）→ **429「账号已被临时锁定」**；A 组（垃圾票 ×5）账号计数**恒为 0** → **证明该 DoS 是验证码失效的直接后果，而非 H2 的遗漏**。

**防线数学**：维持永久锁死只需 **5 次 / 900s = 0.33 次/分钟**。
- 中间件限流 30/min → 占用 **1.3%**
- 签发限流 100/300s → 占用 **5%**
- **IP 失败锁 20/900s → 永不触发**（`ACCOUNT_FAIL_MAX(5) < IP_FAIL_MAX(20)` 且同窗口 → IP 兜底被**结构性架空**）
- 全仓库**无解锁接口** → 15 分钟无法自救；`risk_hit` 只落库、**不触发告警**

**所以 `64fb3c8` 的口径没有闭合**：「验证码 = UX 减速带，防线 = 失败锁定/限流/票据」这句话，把防线交给了一个**入口恰好是验证码**的机制。反向印证：**H2 修复之所以成立，恰恰因为它假设了验证码拦得住。**

## 7. 结论与建议

### 7.1 结论

1. **破解的逻辑**：把验证码降维成「定位唯一暗区」——服务端校验的量、人类任务、攻击者所需，三者是同一个数。
2. **加固的收益**：真实但**仅在内容层**（S1 100% → 20.8% → 0%）。
3. **加固的盲区**：结构层（亮度/色度）与契约层（`sliderY`、只比 x）**完全未动**，最佳正交攻击恒 **100%**。
4. **下游反转**：验证码失效把账号锁从「抗爆破」翻转为「免费 DoS 武器」。

### 7.2 建议（按性价比）

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | **停止下发 `sliderY`**（或改为不在响应中出现 + 补 y 校验） | 契约层漏洞，零成本，直接消灭 S3 |
| **P0** | **账号锁改 `(account, IP)` 复合维度**，纯账号维度降级为告警 | 消除 0.33 次/分钟的 DoS |
| **P0** | 硬锁 → **渐进延迟** `min(2^(n-1), 30)s`；补**自助解锁**与**跨阈值告警** | 消除可用性悬崖 |
| **P1** | 若保留多缺口：**伪缺口必须与拼图块同形**、**同行**、**调色板洗牌** | 消灭 S6/S7/S3（已在 `5a7d074`/`64fb3c8` 部分落地） |
| **P1** | **删除「抗解」宣称**，口径统一为「UX 减速带 + 反通用求解器工具链」 | 避免宣称漂移 |
| **P2** | 评估换范式（ALTCHA PoW 等） | 滑块范式天花板已定 |

### 7.3 基准红线（防回归）

任何后续加固**必须**同时报告以下**正交通道**的成绩，否则视为未测：

- A1/A2 **色度定位**（`S>70`）
- A3/A4 **亮度定位**（滑窗 `argmin` / 暗区连通块）
- S6 **形状比较器**（多缺口模式）
- S7 **明度通道**（多缺口模式）
- 对照基准用 **真实盲猜下界 `(2·tol+1)/(maxX+1) ≈ 9.7%`**，**禁用 `1/k`**
