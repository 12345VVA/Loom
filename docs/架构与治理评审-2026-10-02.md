## 问题清单（按危害排序）

### P0 — 质量保障全靠自觉【已修复 2026-10-04】

> CI 双 job 流水线 e8c3b5d 建成并经 9 轮排障磨合；conftest 测试库防护同批落地。pre-commit 按 2026-10-04 方案决策 D4 暂缓（单人 + CI 兜底）。

**系统性风险，三个维度评审一致的最大发现。**

- 无 CI：无 `.github/workflows`、无 `.gitlab-ci*`、无 `Jenkinsfile`。
- 无 pre-commit（`.pre-commit-config.yaml`）、无 husky/lint-staged。
- `frontend/playwright.config.ts` 引用 `process.env.CI`，但不存在任何会设置它的环境——CI 意识有、落地为零。
- 后果：781+207 个测试、ruff/eslint、type-check 全部处于"无人强制执行"状态；前端 800+ 处 `any` 与巨型组件能无声合入与此直接相关。
- 唯一自动化入口是本地 `scripts/test.ps1`（写得规范），但完全依赖人工自觉执行。

### P1-a — 后端分层名存实亡【已修复 2026-10-04】

> B2 DI 清零三连（bc5655b/4a48643/fab1ff4）：runtime 注册表 + framework 反向依赖白名单收紧为空集全面禁止（4f80a4d→5ffb87b），六道守卫进 CI。残余：core↔framework 包级双向（2026-10-04 重审 M9）。

名义 core → framework → modules，实际双向耦合：

- 框架层十余处反向 import 业务模块：
  - `backend/app/framework/controller_meta.py:18-20` — 直接 import base 模块的 `DeleteRequest/PageResult/User`、`get_current_user`、`PermissionConfig`
  - `backend/app/framework/middleware/admin_authority.py:16`、`scope_authority.py:19`、`rate_limit.py:21`、`operation_log.py:12`
  - `backend/app/framework/router/query_builder.py:12`、`compat_aliases.py:13,63`、`framework/cache.py:8`、`framework/events.py:13`
- core 依赖 modules：`backend/app/core/database.py:16-26` 为 create_all 硬 import 全部 10 个模块的 model；`core/security.py:158,167,180` 延迟 import base 服务。
- 真实循环依赖链存在：controller_meta → base.service.security_service → base.service.authority_service → `app.modules.loader`（authority_service.py:26）→ framework.router.grouping；base.service.admin_service:18 又反向 import controller_meta。目前靠函数级延迟 import 压住，属脆弱平衡，**每新增一个模块都可能加深环**。
- 根因：User / 权限 / 缓存这些框架级关切被放进 base 业务模块，框架只能倒挂。
