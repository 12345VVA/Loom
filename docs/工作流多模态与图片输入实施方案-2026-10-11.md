# 工作流多模态与图片输入实施方案

- 日期：2026-10-11（v1.0；**当日全部实施完成**——四批次 10 提交见文末实施记录）
- 依据：[设计方案 v1.0（2026-10-11）](./工作流多模态与图片输入设计方案-2026-10-11.md)——本文是其**施工计划**：任务分解、执行顺序、验证命令、提交切分与回滚预案。设计细节（数据结构、决策表、转换语义）以设计方案为准，本文不重复，仅引用章节号。
- 执行约定：
  - 直接提交 main；每批次按本文提交序列切分，**每个提交独立可运行、CI 绿**；
  - 后端门禁：`cd backend && venv/Scripts/python.exe scripts/check.py`（ruff 双查 + EPS 契约）；涉及模型/迁移的提交另跑 `venv/Scripts/python.exe -m alembic check`（本地 check.py 不含，CI 有）；
  - 前端门禁：`cd frontend && npm run type-check && npm run test:unit`；**vitest 跑完必查 `git status frontend/build/cool/eps.d.ts`**，被写脏立即还原（后端离线时 vitest 会写降级版）；
  - 新代码不引入显式 `any`（eslint suppressions 只压存量）。

## 1. 批次总览

```
批次 1（阶段一）≈2 人日 ──┬──> 批次 2（阶段二）≈3 人日 ──┬──> 批次 4（阶段四）≈2 人日
                          │                                │
                          └──> 批次 3（阶段三）≈2 人日 ────┘
                               （与批次 2 并行，文件域不相交：
                                media 模块 vs workflow/ai 模块）
```

| 批次 | 主题 | 提交序列 | 前置 |
|---|---|---|---|
| 1 | start 图片声明 + 试运行表单 + 图生图闭环 | 1a → 1b → 1c | 无 |
| 2 | LLM 多模态（DTO/执行器/适配器转换/vision） | 2a → 2b → 2c → 2d | 批次 1（联调需要 image 变量声明） |
| 3 | remote_url + TOS 异步镜像 | 3a → 3b | 无（可与批次 2 并行） |
| 4 | URL 智能调度 + Ingress 闭环 | 4a | 批次 2 + 3 |

每个提交的信息前缀沿用现有风格：`feat(workflow): WFI-x …` / `feat(media): WFI-x …`（WFI = Workflow multimodal Image，任务号见下文）。

## 6. 执行注意事项（历史教训沉淀，逐条适用）

1. **eps.d.ts 陷阱**：前端任何工具链（vitest / dev / build）在后端离线时会写降级版 `build/cool/eps.d.ts`——每次前端命令跑完 `git status frontend/build/cool/eps.d.ts`，脏了 `git checkout` 还原，否则挡后续 stash/stage。
2. **alembic check**：本地 `scripts/check.py` 不含；T3.1 提交前手动 `alembic check`，并确认迁移文件 revision 链正确（`down_revision` 指向 0022）。
3. **eslint suppressions**：修复了被压制问题的文件要跑 `npx eslint --prune-suppressions`，否则 0 errors 仍 exit 2 挂 CI。
4. **locales 三份齐改**：`locale-parity.test.ts` 会校验 key 对齐，漏一份直接红。

## 10. 真机验收记录：TOS 镜像（2026-10-12）

接入真实凭证（ark 自动桶 `ark-auto-2103850221-cn-beijing-default`，cn-beijing）后真机验证发现并修复：

**发现 1 —— ark 自动桶不支持 S3 兼容网关**：boto3 打 `tos-s3-cn-beijing.volces.com`（虚拟主机/path-style 均试）一律 `InvalidPathAccess`。该桶只能走 TOS 原生协议（AromaMemoir 生产同款结论）。修复：`upload_mirror_object` 按端点自动分派——`tos-{region}.volces.com` 原生端点走 `tos` SDK（`requirements.txt` 新增 `tos>=2.9.3`），其余 S3 兼容端点仍走 boto3；两条分支单测覆盖（`test_media_mirror.py` 新增 3 项）。

**发现 2 —— 桶默认私有，必须显式公共读 ACL**：不设 ACL 时对象私有，公网大模型拉图 403（AromaMemoir 注释记录的生产教训）。原生分支 `put_object` 固定携带 `acl=ACLType.ACL_Public_Read`，匿名可读成为 remote_url 的结构保证而非桶策略依赖。

**运维接线**：`docker-compose.yml` worker `-Q` 列表补 `media.mirror` 队列（原列表缺该队列，Docker 部署下镜像任务无人消费）；本地裸启 worker 需 `-Q celery,default,workflow,ai.chat,ai.image,ai.embedding,ai.rerank,ai.audio,ai.video,media.mirror`。

**端到端验证**（生产代码路径 + 真实桶）：`upload_mirror_object` 上传 → 匿名 GET 200（ContentType 保留）→ 探针删除。验收项 ③ 闭环。
