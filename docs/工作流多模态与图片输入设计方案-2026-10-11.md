## 0. 设计目标与总体原则

### 0.1 目标

| 阶段 | 目标 | 对应报告章节 |
|---|---|---|
| 阶段一 | `start` 节点支持 `image` 类型变量；试运行弹窗可视化表单 + 图片上传；打通图生图最小闭环 | 报告 §3.2 / §3.4 / §7 |
| 阶段二 | `llm` 节点支持多模态图片输入：DTO 放宽、执行器组装、适配器协议转换、vision 前置校验 | 报告 §3.3 / §8.2 |
| 阶段三 | `MediaAsset` 增加 `remote_url`，产物转存后异步镜像 TOS（双轨） | 报告 §5 |
| 阶段四 | 图片 URL 消费智能调度：`remote_url` 优先、`__src` 兜底、Ingress 中转、情景 C 前置拦截 | 报告 §4.3 / §8.3 |

### 0.2 强制原则（实施红线）

1. **URL 介质原则**：工作流状态中流转的图片一律为字符串 URL（`/uploads/...` 相对路径、公网 http(s) URL），**严禁 Base64 进入 LangGraph state / 节点日志 / 检查点**。Base64 仅允许在"适配器内转换瞬间"存在。
2. **OpenAI 风格 parts 为中间表示（IR）**：执行器统一产出 `[{"type":"text",...},{"type":"image_url","image_url":{"url":...}}]`；Claude / Gemini 适配器各自负责 IR → 厂商协议转换。不在执行器层做厂商分支。
3. **system 恒为纯文本**：多模态 parts 只允许出现在 user 消息（Claude 适配器 `"\n".join` 对 list 会 TypeError，见探测测试 #3）。
4. **非阻塞镜像**：TOS 镜像失败绝不影响主流程（阶段三核心约束）。
5. **旧图零迁移兼容**：所有配置结构变更向后兼容，无 `type` 的旧声明一律视为 `string`。

### 0.3 非目标（本期不做）

- `human_input` 节点的图片附件反馈（报告 §2 标注"后续演进"）
- 工作流画布内的图片直接拖入节点（仅做 start 变量 + 试运行表单上传）
- 音频 / 视频多模态输入
- TOS 生命周期规则的代码化配置（`wf-temp/` 30 天规则在火山控制台配置，文档说明即可）

## 1. 数据契约设计

### 1.1 输入变量声明 v2（`start` 节点 `config.inputVariables`）

```typescript
// frontend/src/modules/workflow/types（新增 InputVariable 接口）
interface InputVariable {
  name: string;          // 变量名，如 "input_image"
  type: 'string' | 'number' | 'boolean' | 'image';  // 新增，缺省 'string'
  label?: string;        // 显示名（表单模式用）
  required?: boolean;    // 试运行表单校验用
  default?: string | number | boolean | null;  // image 类型不允许 default 为 data URI
  description?: string;
}
```

序列化规则（前端 `start-config.vue` → 图 JSON）：

- `type` 为 `'string'` 时**不落键**（与现有"空默认值不落 default 键"惯例一致），保证旧图字节级不变；
- 旧图读取时 `parseStartInputVariables`（`utils/start-inputs.ts`）统一补 `type: 'string'`——**该函数是前端唯一解析入口**，改造集中于此。

后端 `apply_start_input_defaults`（`tasks/workflow_tasks.py:59`）**不需感知 type**：默认值合并逻辑与类型无关（仅当缺失/空时回落）；类型语义由前端表单与执行器消费端负责。唯一新增：对 `type='image'` 的变量，默认值若为 `data:` 开头字符串直接忽略（防旧图脏数据）。

### 1.2 图片值的合法形态与规范化

工作流中流转的图片值（`inputs` 字典、`image_variables` 引用结果）只允许：

| 形态 | 示例 | 规范化规则 |
|---|---|---|
| 相对 URL | `/uploads/2026/10/xxx.png` | 前端提交前保证以 `/` 开头；执行期由 Ingress 解析（§4.6） |
| 公网 URL | `https://cdn.example.com/a.jpg` | 原样放行 |
| data URI | `data:image/png;base64,...` | **入口拒绝**（§3.6）；仅适配器内部转换时产生 |

非法值处理：`image_variables` 解析结果为空字符串 / `None` → 视为未绑定图（正常执行纯文本）；为 list → 逐项过滤空值。

### 1.3 LLM 节点多模态配置（`config` 增量键）

```json
{
  "modelProfileCode": "gpt-4o",
  "systemPromptTemplate": "你是视觉审核员",
  "promptTemplate": "分析这张图：{input_image}",
  "imageVariables": ["input_image", "cover_image_url"],
  "imageTemplate": "",
  "outputVariable": "output"
}
```

- `imageVariables: string[]`（camelCase，后端经编译期 `convert_keys_to_snake` 读 `image_variables`）：变量引用列表，支持单图 / 多图（数组变量自动展平）；
- `imageTemplate: string`（可选，模板渲染，与 `imageVariables` 互斥优先级：`imageVariables` 优先）——完全对齐 `image_generator` 节点既有的 `imageVariable` / `imageTemplate` 惯例（`service/node_executors.py:474-482`）；
- 值可以是 str 或 `list[str]`（如 batch 上游产出的图片数组），执行器统一展平为 `list[str]`。

### 1.4 `AiRuntimeMessage` DTO 放宽（`model/ai.py:429`）

```python
class AiRuntimeMessage(BaseModel):
    model_config = ConfigDict(populate_by_name=True, alias_generator=resolve_alias)

    role: str
    content: str | list[Any] = Field(union_mode="left_to_right")  # 多模态 Content Parts
```

兼容性（探测测试 #1/#5 已固化）：
- 纯文本调用方（现有全部调用点）零影响——`str` 分支优先匹配；
- `AiSecurityService.check_input_safety` 已扫描 list 中 text part，无需改动；
- `runtime_service.chat` 的 `model_dump()` 对 list content 原样序列化，无需改动。

### 2.4 后端：试运行 / 启动入口 Base64 防线

`WorkflowInstanceStartRequest.inputs: dict[str, Any]`（`model/workflow.py:185`）**结构不改**，在 `workflow_service.py` 的 `start_instance` / `start_trial_instance`（`workflow_service.py:549/570`）入口统一加：

```python
def _reject_inline_data_uris(inputs: dict[str, Any]) -> None:
    """工作流入口拒绝 data URI：图片必须先上传换取 URL（URL 介质原则的入口防线）。"""
    for key, val in (inputs or {}).items():
        values = val if isinstance(val, list) else [val]
        for v in values:
            if isinstance(v, str) and v.startswith("data:"):
                raise HTTPException(
                    status_code=400,
                    detail=f"输入变量 {key} 不支持直接提交 Base64，请先上传图片（试运行弹窗或媒体库）后使用 URL",
                )
```

```python
def _resolve_image_inputs(config: dict, variables: dict) -> list[str]:
    raw: Any = None
    names = config.get("image_variables") or []
    if isinstance(names, str):
        names = [names]
    collected = [variables.get(n) for n in names if variables.get(n)]
    if collected:
        raw = collected
    elif config.get("image_template"):
        try:
            raw = render_template(config["image_template"], variables)
        except Exception as e:
            logger.warning("LLM 节点 image_template 渲染失败，按纯文本执行: %s", e)
    # 展平 + 过滤
    flat = []
    for item in (raw if isinstance(raw, list) else [raw]):
        if isinstance(item, str) and item.strip():
            flat.append(item.strip())
    return flat
```

#### 3.2.4 Gemini：`_gemini_content` 扩展（`adapters/gemini.py:180`）

```python
def _gemini_content(message: dict[str, Any]) -> dict:
    role = "model" if message.get("role") == "assistant" else "user"
    content = message.get("content")
    parts: list[dict] = []
    if isinstance(content, list):
        for p in content:
            if not isinstance(p, dict):
                continue
            if p.get("type") == "text":
                parts.append({"text": p.get("text", "")})
            elif p.get("type") == "image_url":
                url = (p.get("image_url") or {}).get("url", "")
                # 复用既有零件：data URI → inlineData；http URL → SSRF 校验下载后 inlineData
                part = _prepare_gemini_image_part(url)
                if part:
                    parts.append(part)
    else:
        parts.append({"text": str(content or "")})
    if not parts:
        parts.append({"text": ""})   # Gemini 要求 parts 非空
    return {"role": role, "parts": parts}
```

def resolve_consumable_image_url(image_ref: str, *, prefer_remote: bool = True) -> str:
