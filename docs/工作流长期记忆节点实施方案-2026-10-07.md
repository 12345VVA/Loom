### 0.2 新发现缺口一（必须前置解决）：单节点测试路径不设 ctx

**事实**：`WorkflowService.test_node`（workflow_service.py:819-929）建了 `run_type='test_node'` 实例（:848-858）后直接调 `WorkflowCompiler.run_node_standalone`（:869-872），**全程不 set `workflow_instance_id_ctx`**——node_executors.py:542 注释明确「单节点测试路径不设置 ctx，转存资产归属为空」。

**影响**：memory 执行器靠 ctx 拿 instance（→ definition_id / run_type / user_id）。ctx=None 时 store 无法归属、无法推导 env=test，设计文档 §6.1/§8 的「test_node 真实写 test env」**在单节点测试路径不成立**（整图试运行 trial 路径经 workflow_tasks 正常 set ctx，不受影响）。

**解法（已定，任务 T0）**：`test_node` 在执行前 `workflow_instance_id_ctx.set(instance.id)`、finally reset——单节点测试本来就落库测试实例+单行日志（P1-4），ctx 指向它语义自洽。

**行为变化评估（接受）**：
- 生图节点单节点测试：转存资产从「归属为空（仅超管可见）」变为「归属 test_node 实例 + 测试发起者」——**更准确的归属**，且 test_node 实例不进正式列表；
- call log：单节点测试的 LLM 调用归因到 test_node 实例——`workflow_eval` 聚合时 test_node 实例本就独立，影响中性；
- `test_media_workflow_attribution.py:106` 断言不受影响（它直接调 `_persist_image_to_media` 测 ctx=None 防御分支，该分支保留）；
- node_executors.py:540-542 注释同步更新。

**独立提交**（纯行为修复+测试，可独立回滚，不夹带 memory 功能）。

### 0.3 新发现缺口二：`run_ai_embedding` 不存在 + 放置位置决策

**事实**：设计文档 §5.4 的 `run_ai_embedding` 封装**当前不存在**（node_executors.py 只有 `run_ai_chat`:63 / `run_ai_image`:101；ai 模块只有 `AiModelRuntimeService.embedding`:322）。

**位置决策：放 `workflow_memory_service.py`，不放 node_executors.py**。理由：
- 依赖方向必须单向 `node_executors → workflow_memory_service → ai runtime`。若放 node_executors，则 store 执行器（node_executors）→ upsert（memory_service）与 memory_service 管理页 add → run_ai_embedding（node_executors）形成**循环导入**；
- 它是 memory 域专属契约（返回 `(vector, space)` 二元组、失败态裸 code、未配置态 None——§5.4），不是通用 AI 封装；
- 现有「AI 封装集中在 node_executors」的组织（:60 注释）让位于无循环依赖的硬约束。

**实现契约**（对应设计 §5.4，含 v5.2 失败态）：

```py
def run_ai_embedding(text: str, profile_code: str | None = None) -> tuple[list[float] | None, str | None]:
    # 1. registry.resolve(model_type="embedding", scenario="default", profile_code=profile_code)
    #    捕获 HTTPException(404) → return (None, None)            # 未配置态（§4.5 第一行）
    # 2. runtime.embedding(AiEmbeddingRequest(profile_code=..., input=text))
    #    异常/success=False/空 data → return (None, resolved["model"].code)   # 失败态：裸 code（§4.5）
    # 3. vector = data[0]["embedding"] → return (vector, f"{code}:{len(vector)}")  # ready 态
```

注意：resolve 先于调用（model code 不依赖调用成败，v5.2 澄清 D）；`runtime.embedding` 内部 `_resolve_with_options` 会二次 resolve（轻量查询，可接受，不绕私有 `_invoke`）。

**写路径核心 API（供 store 执行器，独立 session 由执行器 to_thread 内管理）**：

```py
def upsert_memory(
    session, *, definition_id: int, memory_env: str, content: str,
    memory_key: str | None, memory_type: str, tags: list[str],
    embedding: list[float] | None, embedding_space: str | None,
    source_instance_id: int | None, source_node_id: str | None,
    source_run_type: str, user_id: int | None,
) -> tuple[int, str]:
    """三级判定 + 并发防重 + 容量保护。返回 (memory_id, action)。
    action ∈ created | updated | deduplicated（skipped/degraded 在执行器层）。"""
```

实现要点（全部对应设计 §4.2/§5.3，v5.1/v5.2 口径）：

1. **快路径 SELECT**：有 key → 按 (definition_id, memory_env, memory_key) 查活跃行；无 key → 按 content_hash 查活跃行（hash 用 normalize 后值）；
2. **key upsert**：命中 → UPDATE content/tags/embedding/content_hash + 刷新 `source_instance_id/source_node_id/source_run_type` + `updated_by_user_id=user_id`（created_by/created_at 不动），action=updated；
3. **hash 去重**：无 key 命中 → 返回既有 id，action=deduplicated（**首写为准**，后写丢弃，§5.3 v5.2）；
4. **INSERT**：新行 `created_by_user_id = updated_by_user_id = user_id`；捕获 `IntegrityError` → **rollback 重走完整判定**，按异常约束名区分：撞 `uq_mem_key` → 重走后进 UPDATE 分支（**后写者 content 胜出**，action=updated）；撞 `uq_mem_hash` → 返回既有 id（deduplicated）；SQLAlchemy 异常对象取约束名（`orig.diag.constraint_name`（PG）/ 解析 message（SQLite）——封一个 `_integrity_target(exc) -> str | None` 辅助函数，双栈实现）；
5. **语义相似 warning**：仅无 key 新 INSERT 前后（写前比对最近 `WORKFLOW_MEMORY_DEDUPE_WINDOW` 条活跃行）；仅对 ready 态（embedding 非空且 space 含 `:`）行算余弦，≥`WORKFLOW_MEMORY_DEDUPE_SIMILARITY` 记 **warning 日志不丢弃**；窗口内无 ready 行**零开销跳过**（§5.3 v5.2）；
6. **容量保护（先插后淘，§4.4）**：INSERT 提交后按 (definition_id, memory_env) 数活跃行，> `WORKFLOW_MEMORY_SCOPE_CAP` → 按 `COALESCE(last_accessed_at, updated_at, created_at)` 最旧 `WORKFLOW_MEMORY_EVICTION_BATCH` 条软删（置 delete_time）+ warning 日志；不加锁、容忍并发短暂超限；
7. `content > WORKFLOW_MEMORY_MAX_CONTENT_LENGTH` 在执行器层拦截（service 层二次断言防御）。

**另两个生命周期 API**：

- `cascade_soft_delete_by_definition(session, definition_id: int) -> int`：一条 `UPDATE ... SET delete_time=now WHERE definition_id=? AND delete_time IS NULL`（T4 挂点调用）；
- `sweep_memory_tombstones(keep_days: int, batch_size: int = 500) -> int`：`delete_time < now - keep_days` 硬删，分批（T4 sweep 调用）。

### T5 execute_memory_store_node

**`node_executors.py`**（新执行器 + 注册）：

```py
async def execute_memory_store_node(variables, config) -> dict[str, Any]:
    """长期记忆写入节点。幂等性自警：节点逻辑具备去重能力（key upsert + hash 防重），
    但副作用一致性由节点逻辑保证而非框架——仍声明 idempotent=False，重试框架强制

```

执行流程（设计 §6.1 十步，落点映射）：

1. `content = render_template(get_config_value(config, "contentTemplate"), variables)`；
2. 写权限：to_thread 内独立 SessionLocal 查 `WorkflowDefinition.memory_write_enabled`；False → raise（中文可定位错误：「工作流未开启记忆写入（memoryWriteEnabled），无法保存长期记忆」——X-1 口径 fail-fast，**不静默 skip**）；ctx 无 instance 时同样 fail（单节点测试经 T0 已有 ctx）；
3. env 门控：instance.run_type——`eval → return {memory_id: None, memory_action: "skipped"}`（delta 键经 output_variable 机制）；`test_node → memory_env="test"`；其余 production；
4. 归属：`definition_id = instance.definition_id`（ctx → instance，**绝不读 variables/config**，§9.1）；`user_id = instance.user_id`；
5. 空 content / 超长（> settings.WORKFLOW_MEMORY_MAX_CONTENT_LENGTH）→ raise（不截断）；
6. 凭据检测：`detect_credential_patterns(content)` 命中 → logger.warning（不阻断）；
7. `memory_key = render_template(memoryKeyTemplate, variables) if 配了 else None`（渲染后空白 → None）；
8. embedding：`await asyncio.to_thread(run_ai_embedding, content, config.get("embedding_profile_code"))` → (vector, space)（失败/未配置按 §0.3 三态）；

10. 返回 delta：`{config.get("output_variable", "memory_id"): memory_id, "memory_action": action}`。

- `onError: "degrade"`：步骤 2/5/8-9 的异常捕获 → `{memory_id: None, memory_action: "degraded"}`（**不 raise**——显式降级是配置语义，非静默吞错；默认 `fail` 全部冒泡）；
