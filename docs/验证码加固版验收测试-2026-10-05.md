## 0. 结论摘要

| 结论 | 判定 |
|---|---|
| 加固对**原 §13 求解器**有效 | ✅ 20.8%，且低于「定位后随机挑候选」的 40.6% 下界（亮度补偿产生了误导性匹配） |
| 「朴素求解器 100% → 盲猜水平」的表述 | ⚠️ **字面属实、结论不成立**。用户只测了自己那一个求解器；换三条路径，命中率分别 **100.0% / 99.2% / 96.7%** |
| 加固使验证码整体回到「盲猜水平」 | ❌ **不成立**。三条**确定性**旁路，零机器学习、零 OCR、纯 CPU 毫秒级 |
| 真实浏览器能否复现 | ✅ 已复现。**两条独立路径**各自拿到 **HTTP 200 + access token**，完整登录成功 |

**一句话**：加固把「**内容匹配**」这条路堵死了（这是真本事），但它试图把判别压力转移到「形状」和「色调/明度」上 —— 而这两个通道**都是机器可读的标量/几何特征**，且都是**代码里显式设计出来的**。加固没有改变「人类专属通道 == 机器可读通道」这个结构性事实。

## 1. 加固做了什么（源码核验）

`backend/app/modules/base/service/auth_captcha_render.py`（419 行新增，纯函数管线）：

| 手段 | 实现 | 意图 |
|---|---|---|
| 背景压暗 | 中灰 100-160（legacy 180-230） | 让 §13 的亮度补偿 `×255/145` 把全图饱和成白场 |
| 洞内噪声替换 | `hole_noise_sigma=25` | 切断「洞内 = 原图 × 常数」的加性模型 |
| 拼图块补偿呈现 | `_COMPENSATE_LUT`，块整体 ×1.76 变亮 | 真人看着舒服，让模板匹配失去线性关系 |
| 异形缺口 | `PUZZLE_SHAPES = rounded/knob/circle/capsule` + `rotate_deg=6.0` | 形状不可预期 |
| 伪缺口烧票 | `layout_decoys`，x 轴间距 `≥ puzzle_size + 20` | 候选从 1 个变 2-3 个 |
| 色调判别 | `pick_tints(rng, 1+len(decoys))` 色相均布 + **明度逐档错开** | 真人判别通道（文档明写「色觉障碍用户可按明度匹配」）|

开关：`CAPTCHA_PUZZLE_HARDENING=True`；`False` 回退 `_render_captcha_images_legacy()`。
**运行态确认**：实测 bg 中灰像素占比 **91.9%**（legacy 浅色 180-230 仅 0.4%）→ 加固版已生效。

## 2. 离线精确基准（120 样本，seed=20261005）

真值直接取自渲染管线的 `RenderResult.decoys`，全部攻击只使用响应中**实际公开**的字段（`bg` / `slider` / `sliderY` / `tolerance` / `sliderWidth=44`）。

| 编号 | 攻击策略 | 命中 | 命中率 |
|---|---|---|---|
| **S1** | §13 亮度补偿 `×255/145` + 滑窗模板匹配（**用户所称的朴素求解器**） | 25/120 | **20.8%**（0px 精确 19） |
| **S2** | 定位缺口后**随机**挑一个（对照下界） | 48.7/120 | **40.6%** |
| **S3** | 缺口描边定位 + 取「锚点 y 最接近 `sliderY`」者 | 116/120 | **96.7%**（精确 61） |
| **S4** | 候选框 44×44 区域均值色调匹配（粗） | 85/120 | **70.8%** |
| **S5** | 在 `y=sliderY` 行内找最暗窗口 | 77/120 | **64.2%** |
| **S6** | **形状比较器**：暗区提掩码 → bbox 归一化 → 与拼图块 alpha 求 IoU | **120/120** | **100.0%** |
| **S7** | **明度通道**：掩码内均值明度最高者 | **119/120** | **99.2%** |
| — | 缺口定位/提取正确率 | 120/120 | **100.0%** |

候选数校验：伪缺口分布 1 个 → 52 次、2 个 → 68 次，候选/图 = 2.567（理论 2.5）✓

**读法**：
- S1 = 20.8% **低于** S2 = 40.6%：加固对「内容匹配」不只是失效，而是**主动误导** —— 这一项确实有效。
- S6 = **100.0%**、S7 = **99.2%**：换任何一条**不用看懂图像内容**的路径，命中率立刻回到天花板。
  - S6 真缺口**始终排在 IoU 第 1 名**（最小领先量 0.017，恒正）
  - S7 真缺口**始终是最亮的**（明度领先量均值 4.65，最小 0.33，恒正）

## 3. 四条旁路的根因（源码定位）

### 3.1 ★★★ P0：伪缺口被**强制异形** → 形状即答案（S6 = 100%）

```python
decoy_shape = rng.choice([s for s in PUZZLE_SHAPES if s != shape and s not in decoy_shapes])
```
> 原注释：「伪缺口异形（≠拼图块形状、彼此互异）——**形状即真人判别通道**（不受色觉影响），
> 而**朴素内容匹配求解器没有形状比较器**，选中伪缺口即烧票」

**这句注释就是致命误判**：形状比较器是几行代码的事。

```python
# 攻击者只需三步（全部只用公开信息）
pm   = piece.getchannel("A") > 127          # ① 拼图块 alpha == 洞口掩码（构造性咬合）
   # ② bg 灰度低分位阈值 → 连通域 → 每个洞口掩码（洞内被黑 110 压暗，直接可分割）
   # ③ 两者 bbox 归一化到 44×44 后求 IoU，取最大者
```

`PUZZLE_SHAPES` 只有 4 种，且伪缺口被**保证**与拼图块不同 → 这是一个「答案必定互异」的 4 分类问题。实测 120/120。

**实测样本（浏览器抓取，`annotated_solve_s6.png`）**：拼图块是**胶囊形**，真缺口是**胶囊形**（x=141），伪缺口是**圆形**（x=75）。肉眼一眼可辨 —— 机器更是一眼可辨。

### 3.2 ★★★ P0：`pick_tints` 明度单调错开 → 真缺口恒为最亮（S7 = 99.2%）

```python
def pick_tints(rng, count):
    """判别色调调色板：色相均布无碰撞，**明度逐档错开（色觉障碍用户可按明度匹配）**。"""
    for index in range(count):
        hue = (start + index * 256 // max(1, count)) % 256
        value = 235 - index * 40          # ← 单调递减
        ...
tints = pick_tints(rng, 1 + len(decoys))
true_tint = tints[0]                       # ← 真缺口恒为第 0 个 = 最亮
```

这是**为无障碍刻意设计**的通道：让人（含色觉障碍者）按明度找出真缺口。但它同时也是一个**标量**，机器读取的成本为零。S7 = 119/120。

> 这是一个**设计层面的内在冲突**：任何「让人类能识别真缺口」的线索，按定义就是「让机器能识别真缺口」的线索。加固把判别依赖从「内容」搬到「明度」，只是把攻击者从「模板匹配」换到「取 argmax」而已。

### 3.3 ★ P0：`sliderY` 就是答案的 y，且服务端从不校验 y（S3 = 96.7%）

```python
# captcha()
target_y = secrets.randbelow(height_int - puzzle_size + 1)
return {..., "sliderY": target_y, ...}      # ← target_y 明文下发
# captcha_check()
if abs(final_x - target_x) > tolerance:      # ← 只比 x
```
前端拼图块必须画在正确行上（`top: ${sliderY}px`），所以 y 一定会下发；而校验只比对 x → y 是一份**免费答案**。攻击者用白描边框出全部缺口（**100% 可定位**），取「y 最接近 `sliderY`」者 → 40.6% → 96.7%。

> 该侧信道在 legacy 同样存在，但 legacy 靠 S1 已 100%，问题被掩盖。**加固把「x 通道堵死」变成了「只剩 y 这根稻草」，反而让 y 侧信道成为主攻路径。**

### 3.4 P0：白色描边是结构性信标，且加固**放大**了它的对比度

```python
ring = mask_ring(hole_mask, width=2)                                  # 外环
_alpha_blend_masked_into(overlay, (255,255,255), ring, 220, (x, y))   # 纯白 2px
```
`mask_ring` 注释：「配合噪声线条**防 OCR 定位缺口**」。但背景压暗后对比度反而更大：

| 版本 | 背景亮度 | 描边 | 对比差 |
|---|---|---|---|
| legacy | 180-230 | 255 | **25-75** |
| 加固后 | 100-160 | 255 | **95-155** |

阈值 `min(RGB) > 190` 一条就 100% 框出全部缺口。**「找到缺口」不可能也不应该成为难点**（真人也要靠它对齐）；难点必须全部落在「**区分真假**」上 —— 而 3.1/3.2/3.3 把「真假可区分」做成了确定性的。

## 5. 验收判定

| 项 | 判定 | 依据 |
|---|---|---|
| 「朴素求解器 100% → 20.8%」 | ✅ 数据属实 | 离线 120 样本，S1 = 20.8% |
| 「回到盲猜水平」 | ❌ **结论不成立** | 真实下界 S2 = 40.6%；而攻击者实际能力是 S6 = 100.0% / S7 = 99.2% |
| 加固作为反**内容匹配**手段 | ✅ 有效 | S1 被压到低于随机下界，噪声替换/补偿呈现确实打断了加性模型 |
| 加固作为**安全控制** | ❌ 无增益 | 浏览器双路径 200 + token |

**公允评价**：这是一次**有真本事但方向错位**的加固。图像域（让求解器读不懂洞与块的内容关系）做得扎实；但信息域（让攻击者分不清哪个洞是真的）被**四条确定性泄漏**整体击穿，净安全增益 ≈ 0。而且其中最关键的两条（形状、明度）是**加固自身显式设计出来、并写在注释里的**。

## 6. 修复建议

### 先明确一个不得不承认的前提
本报告 S6/S7 证明：**只要真缺口存在任何「人类可感知的判别线索」，该线索就必然机器可读。** 因此：

- 若坚持滑块形态 → 只能把攻击成本从「10 行」抬到「100 行」，**无法抬到「不可行」**；
- 真正有效的方向是**换掉验证范式**（见 `docs/开源行为验证与拼图验证码调研-2026-10-05.md` 的 ALTCHA PoW 推荐），或**明确把滑块降级为 UX 减速带**，把安全责任交给账号锁 + IP 锁 + 限流。

### 若仍要修补滑块，按此优先级

**P0-1 形状不得携带答案信息**
删除 `decoy_shape != shape` 约束：**所有缺口使用与拼图块相同的形状**（同一 `hole_mask`，可只随机旋转角）。
- 代价：形状不再是真人判别通道；
- 收益：S6 从 100% 归零。

**P0-2 明度不得与「真/伪」绑定**
`pick_tints` 的 `value` 必须是 `rng` 独立取值（或生成后 `shuffle`），**真缺口不得固定在 index 0**。
- 直接消除 S7（99.2%）；
- 注意：这会牺牲「色觉障碍用户按明度匹配」这一无障碍设计 —— 需产品决策。可改为「所有缺口同色相、同明度，靠**位置/形状**区分」，但形状已被 P0-1 关闭 → 于是只剩「内容/色调方向」；色调方向仍可读（S4=70.8%），故必须同时做 P0-3。

**P0-3 消除 `sliderY` 侧信道 + 补 y 校验**
① 伪缺口 y **强制等于 `target_y`**（`layout_decoys` 只沿 x 分离）；
② `captcha_check` 增加 y 校验，前端 `buildVerifyCode` 一并上报 `y`（当前只报 x，`pic-captcha.vue:144-152`）。
- 直接消除 S3（96.7%）。注意此项**与 P0-1 无关**，必须独立修。

**P1 描边不得成为「真假」的定位依据 + 修正注释**
- 三处描边样式已一致（✓），无需改；P0-1 落地后此条自然缓解。
- 修正 `_random_bg_color` 的注释：「防 OCR 定位缺口」不成立 —— 压暗背景实际**增强**了白描边对比度。

**P1 修复后必须重跑基准并给出新红线**
- 必须包含 **S6（形状 IoU）与 S7（明度 argmax）** 两个策略，否则会重复「只测自己那个求解器」的误判；
- 目标：**任何单一策略 ≤ 40.6%**（不优于「定位后随机挑候选」）。

**P2 归因记录**
- 本报告的 S1/S3/S6/S7 应回填 `docs/登录链路验证码专项分析-2026-10-05.md`；
- **不要再引用「加固后命中率 12-16%」作为已验收结论**。
